# IQ-TREE 2.4.0 discrete-Gamma (`+G`) site-rate fixtures

These files were generated by the installed IQ-TREE 2.4.0 ARM64 release. The
alignment is *simulated* (rather than an empirical tiny alignment) so the fitted
Gamma shape is moderate and the discrete-category rates are non-degenerate and
representable to writer precision.

## Simulation

`alignment.fasta` was simulated with `--alisim` under a well-conditioned
`GTR+F+G4{0.7}` process on the fixed 10-taxon `tree.nwk`, then converted from the
emitted PHYLIP to FASTA:

```sh
iqtree2 --alisim sim_aln -t tree.nwk \
  -m "GTR{2.0,4.0,1.0,1.2,5.0}+F{0.3,0.2,0.2,0.3}+G4{0.7}" \
  --length 400 --seed 1 -redo -nt 1
```

## `unpartitioned/` — `GTR+F+G4`

```sh
iqtree2 -s alignment.fasta -te tree.nwk -m GTR+F+G4 \
  --rate -wslr --prefix generated --seed 1 -redo -nt 1
```

The report fits `Gamma shape alpha: 0.7875` and prints the
`Category Relative_rate Proportion` table (equal `0.25` proportions; MEAN-method
relative rates `0.0929, 0.4021, 0.9534, 2.552`). TreeTime reads the category
rates directly from that table (the same table used for `+R`). The `.sitelh`
(from `-wslr`) holds per-site, per-category log-likelihoods; the rate-category
responsibility is reconstructed as `q_k = exp(LnLW_k - LnL)` — identical to the
`+R` path (no invariant category). The optional `.rate` cross-check confirms the
posterior-weighted mean rate matches IQ-TREE's own per-site `Rate` column.

## `partitioned/` — two contiguous `GTR+F+G4` partitions

`partitions.nex` is a *charset-only* NEXUS file (a `charpartition` with explicit
models conflicts with `-m`, so `-m GTR+F+G4` applies per partition):

```sh
iqtree2 -s alignment.fasta -te tree.nwk -p partitions.nex -m GTR+F+G4 \
  --rate -wslr --prefix generated --seed 1 -redo -nt 1
```

Unlike `+R`, the partitioned `best_model.nex` writes only the shape per
partition (`...+G4{0.792265}: first{...}` and `...+G4{0.794274}: second{...}`) —
there is NO explicit per-category rate table, the report has NO per-partition
`Category` table, and `.rate`'s `C_Rate` alone is insufficient. TreeTime
therefore recomputes each partition's category rates from `alpha` using the
mean-method discrete-Gamma (validated in
`test_site_rate_model.py` against IQ-TREE's own unpartitioned `Category` table).
The report's `Speed` column supplies the per-partition speeds (`1.0183`,
`0.9726`) that scale those category rates onto the shared branch-time process.
